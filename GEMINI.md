# CyberShield Development Rules

## Workflow Rules
1. **New Features**: Always run `brainstorming`, followed by `writing-plans`, before writing any implementation code.
2. **Bug Fixing**: Always use `systematic-debugging` first to reproduce, diagnose, and isolate issues before proposing fixes.
3. **Implementation Quality**: All new code must follow `test-driven-development` (TDD) and pass `verification-before-completion` with tangible test evidence.
4. **UI/UX Work**: Consult the `ui-ux-pro-max` skill first and follow its generated design system and accessibility guidelines.

## Project Context & Safety
- **Product Name**: CyberShield
- **Source of Truth**: Planning and architecture specifications live in `/docs`.
- **Sandbox & Security**: Never execute, import, evaluate, or install dependencies from scanned third-party repositories.
